# 3.4.11 更新恢复与无障碍验证

日期：2026-11-19。版本 3.4.11，versionCode 115。

- Debug、五种架构 Release 与 Release Lint 构建通过，Lint 为 0 错误、141 警告。新增同步保存提示对应更新前必须持久保存开关意愿的逻辑。
- 五种 Release 安装包的包名、版本及签名校验通过，与 3.4.10 保持相同签名。
- 独占模拟器中进行真实 APK 覆盖安装：开启的悬浮球恢复且窗口挂载，已手动关闭的保持关闭。授权的无障碍在覆盖安装后重新连接。
- 模拟更新广播没有写入待恢复标记：保存的开关仍为开启，再次打开应用成功恢复。手动关闭后再次打开不启动。
- 模拟悬浮窗授权缺失：保留开启意愿和待恢复状态；恢复授权并返回应用后显示悬浮球。无障碍关闭时，普通悬浮球仍可独立显示。
- 7 项服务授权组件解析检查通过，包括空值、完整名称、简写名称、多服务列表与避免前缀误匹配。
- 模拟器中验证无障碍连接与断开后，首页状态无需重新打开即可刷新。另验证 UI 自动化工具会临时压制服务，工具退出后重新连接；因此索尼覆盖安装验证不使用该工具。
- 最终版授权说明截图核对通过，提供「去开启」「应用信息」入口及「受限制的设置」处理步骤。
- 索尼 A202SO 的真实原因：系统辅助功能列表将空叶置灰，点击显示「受限制的设置」；检查对应限制为 ignore。通过系统应用信息菜单允许受限制的设置，再在系统页面开启无障碍。
- 随后在索尼上两次覆盖安装 3.4.11，未打开应用前均检查到无障碍授权保留、AssistService 存在及 FloatService 在前台运行；最终首页显示无障碍已连接、悬浮球运行。未卸载、清除数据或更改通知授权。
- 普通应用不能替代用户授权，也不能可靠查询受限制设置状态；最终实现只使用真实无障碍授权和连接状态，并提供条件说明，没有申请额外查询权限。

截图位于 `docs/screenshots/3.4.11/`：`sony-accessibility-detail.png` 为系统限制提示，`sony-restricted-result.png` 为系统允许结果，`sony-updated-home.png` 为最终状态，`emulator-accessibility-guidance.png` 为应用内说明。

系统处理步骤参考：[Android 帮助：受限制的设置](https://support.google.com/android/answer/12623953)。本次验证覆盖 APK 更新，不保证卸载重装保留设置和授权。
